## Overview

Pawa HR is an internal HR platform designed to give organisations complete visibility over their workforce and finances. It combines employee lifecycle management with budget tracking, expense recording, and department-level analytics — all surfaced through an interactive Next.js dashboard.

---

## Features

### 👥 Employee Management
- Create, update, and deactivate employee profiles
- Track contract type (Permanent / Contract / Graduate Trainee)
- Record hire dates, termination dates, salary, and airtime allowance
- Assign employees to departments

### 🏢 Department Management
- Create and manage departments
- View per-department headcount

### 💰 Budget & Expense Tracking
- Set an annual budget per year
- Record expenses across categorised types (Transportation, Accommodation, Recruitment, Training, Welfare, Legal, Engagement, System, Airtime)
- Inline budget editing with live percentage-used progress bar
- Prevent recording expenses for future months (guard rail)
- Export expense reports to PDF via browser print

### 📊 Analytics Dashboard
- Department headcount breakdown
- Retention rate (per department & company-wide)
- Average employee tenure
- Monthly headcount trend chart
- Monthly expenses vs. budget chart (with payroll included)
- Spend-by-category pie chart
- Period filtering: monthly, quarterly (Q1–Q4), and yearly views

## Data Models

### Employee
| Field | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key |
| `name` | String | Required |
| `email` | String | Unique |
| `role` | String | Job title |
| `dept_id` | FK → Department | Required |
| `contract_type` | Enum | `permanent`, `contract`, `graduate_trainee` |
| `salary` | Float | Monthly gross |
| `airtime_allowance` | Float | Monthly allowance |
| `hire_date` | DateTime | |
| `termination_date` | DateTime | Nullable |
| `is_active` | Boolean | Default `true` |

### Department
| Field | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key |
| `name` | String | Required |

### Budget
| Field | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key |
| `month` | String | Stores the **year** (e.g. `"2026"`) — annual budget |
| `amount` | Float | Annual budget in KES |

### Expense
| Field | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key |
| `description` | String | Required |
| `amount` | Integer | Amount in KES |
| `expense_type` | String | See categories below |
| `date` | DateTime | Expense date |
| `budget_id` | FK → Budget | Required |

**Expense Categories:** `TRANSPORTATION`, `ACCOMMODATION`, `SALARY`, `AIRTIME`, `RECRUITMENT`, `EMPLOYEE`, `TRAINING`, `SYSTEM`, `WELFARE`, `ENGAGEMENT`, `LEGAL`

## Getting Started

### Prerequisites

- [Docker](https://docs.docker.com/get-docker/) and Docker Compose (for the containerised setup)
- **Or**, for local development:
  - Python 3.11+
  - Node.js 20+ and Yarn
  - MySQL 8.0 running locally

---

### Environment Variables

#### Backend — `backend/.env`

```env
APP_NAME=Pawa HR
APP_VERSION=1.0.0
DATABASE_URL=mysql+pymysql://root:root@db:3306/pawa_hr
MYSQL_HOST=db

# Auth
NEXTAUTH_SECRET=your_secret_here
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60

# Google OAuth (optional)
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REDIRECT_URI=

# Default admin seed
DEFAULT_ADMIN_EMAIL=admin@example.com
DEFAULT_ADMIN_PASSWORD=changeme

# CORS
ALLOWED_ORIGINS=http://localhost:3000
```

#### Frontend — `frontend/.env`

```env
NEXT_PUBLIC_API_URL=http://localhost:8000
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=your_secret_here

# Google OAuth (must match backend)
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
```

#### Root — `.env` (used by Docker Compose)

```env
MYSQL_ROOT_PASSWORD=root
DB_NAME=pawa_hr
NEXTAUTH_SECRET=your_secret_here
NEXTAUTH_URL=http://localhost:3000
NEXT_PUBLIC_API_URL=http://backend:8000
ALLOWED_ORIGINS=http://localhost:3000
```

### Running with Docker (Recommended)

1. **Clone the repository**
   ```bash
   git clone <repo-url>
   cd pawa-hr
   ```

2. **Create the root `.env`** with the values shown above.

3. **Build and start all services**
   ```bash
   docker compose up --build
   ```

   This will:
   - Start a MySQL 8.0 database (`pawa_hr_db`)
   - Wait for the database to be healthy, then run Alembic migrations automatically
   - Start the FastAPI backend on **port 8000**
   - Build and serve the Next.js frontend on **port 3000**

4. **Access the apps**
   - Frontend: [http://localhost:3000](http://localhost:3000)
   - API Docs (Swagger): [http://localhost:8000/docs](http://localhost:8000/docs)

### Running Locally

#### Backend

```bash
cd backend

# Create and activate a virtual environment
python3.11 -m venv venv
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Configure backend/.env with a local DATABASE_URL, e.g.:
# DATABASE_URL=mysql+pymysql://root:password@localhost:3306/pawa_hr

# Run migrations
alembic upgrade head

# Start the dev server
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

#### Frontend

```bash
cd frontend

# Install dependencies
yarn install

# Configure frontend/.env
# NEXT_PUBLIC_API_URL=http://localhost:8000

# Start the dev server
yarn dev
```

The frontend will be available at [http://localhost:3000](http://localhost:3000).

## Database Migrations

Migrations are managed with **Alembic**. The container runs them automatically on startup via `scripts/start.sh`.

For manual migration operations:

```bash
cd backend
source venv/bin/activate

# Apply all pending migrations
alembic upgrade head

# Rollback one migration
alembic downgrade -1

# Generate a new migration from model changes
alembic revision --autogenerate -m "describe your change"

# Check current revision
alembic current
```

## Authentication

Authentication is handled client-side by **NextAuth.js**. The system supports:

- **Google OAuth** — configure `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` in both `.env` files.
- **Credentials** — a default admin account is seeded via `DEFAULT_ADMIN_EMAIL` and `DEFAULT_ADMIN_PASSWORD`.

The backend uses **JWT tokens** (HS256) to validate requests. The shared `NEXTAUTH_SECRET` is used as the signing key.

## Analytics Engine

The analytics service (`backend/services/analytics.py`) computes all dashboard metrics on the fly from the database. Key calculations:

| Metric | Description |
|---|---|
| **Department Headcount** | Employees active as of the last day of the selected period |
| **Retention Rate** | Active employees ÷ total ever employed, per department and globally |
| **Average Tenure** | Mean years of service for currently active employees |
| **Payroll** | Sum of salary + airtime allowance for all employees active in each month of the period |
| **Budget % Used** | (Total expenses + Total payroll) ÷ Annual budget |
| **Expenses vs. Budget** | Monthly breakdown of actual spend against a pro-rated monthly budget |
| **Category Breakdown** | Expense totals grouped by type, with payroll added as "SALARY" |
| **Headcount Trend** | Total active employees per month for the selected period |

Period parsing supports `YYYY-MM`, `YYYY-QX` (quarter), and `YYYY` (full year) formats.

## Deployment

The project has been deployed to **Google Cloud Run** using **GitHub Actions** with **Workload Identity Federation** for keyless GCP authentication. The pipeline:

1. Builds Docker images for both backend and frontend
2. Pushes images to **Google Artifact Registry**
3. Deploys to Cloud Run with the correct environment variables and Cloud SQL connectivity
